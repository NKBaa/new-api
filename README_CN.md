# 这份代码是什么？—— 白话说明

> 本文档写给**不写代码的人**看。读完你能明白：这套代码加了什么功能、怎么用、以及将来官方更新了怎么升级。
>
> 想看技术细节请读 `UPGRADE_GUIDE.md`（那是写给 AI 和程序员看的）。

---

## 一、一句话说明

我们在**官方 New API 原版**的基础上，加了 **11 项自己需要的功能**。

**关键点：只加功能，不改官方原有的东西。** 官方代码就像一栋楼，我们只是在里面加装了 11 件家具，没有拆墙、没有改结构。这样以后官方翻新大楼时，我们的装修很容易搬过去。

---

## 二、到底加了哪 11 项功能？

### 1. 充值返佣（推广分润）
**做什么**：用户 A 推荐了用户 B，B 充值时 A 能自动拿到一定比例的返佣。

**你会在哪看到**：个人中心 → 推广/返佣卡片，能看到自己拉了多少人、拿了多少返佣。

**怎么设置**：后台设置里填返佣比例（0~100%）。

**为什么可靠**：返佣和充值在**同一个数据库事务**里完成——要么都成功，要么都不发生。并且用数据库的唯一索引防止"同一笔充值被重复发佣"（网络重试、并发回调都不会重复发钱）。

---

### 2. 推荐计划说明文字可自定义
**做什么**：推荐页面那段说明文字，你可以自己在后台改，不用改代码。

**怎么设置**：后台填一段文字；不填就显示默认文案。

---

### 3. 普通用户看不到"模型被替换"的细节（防穿帮）
**做什么**：你在后台配置的模型映射（比如把便宜的模型伪装成贵的），**普通用户看不到真相**，只有管理员能看到完整信息。

**为什么重要**：这是商业保密需求——不能让用户发现"我买的是 A 模型，实际给我的是 B 模型"。

**注意**：管理员切换成"只看自己"的视图时，也会被当作普通用户对待（不会意外泄露）。

---

### 4. 全站默认主题 + 导航栏圆角
**做什么**：你可以给**所有用户**设一个统一的默认外观（深色/浅色、配色、圆角等）。

**用户自由度**：用户自己改了外观后，就固定用他自己的；用户点"重置"就回到你设的全站默认。

**新增**：导航栏圆角单独可调（6 档）。

**注意**：我们**没有**改官方的主题基础文件，只是"设定默认值"和"记录用户自己的选择"。

---

### 5. OpenRouter 风格极简首页
**做什么**：多了一套干净简洁的首页（类似 OpenRouter 那种风格），可以在路由里切换。

**重要**：官方原来的首页**一个字都没改**，两套并存。你觉得新首页不好，随时切回官方原版。

---

### 6. 防黑产 / 防薅羊毛
**做什么**：防止有人批量注册小号、用脚本自动签到薅羊毛。有 4 道关卡，每道都能单独开关：

| 关卡 | 作用 |
|---|---|
| 充值门槛 | 只允许**充过值或兑换过卡密**的用户签到 |
| 自动化 UA 拦截 | 拦掉常见的脚本/机器人 User-Agent |
| 单 IP 每日签到上限 | 一个 IP 一天最多签到几次 |
| 单 IP 注册上限 | 一个 IP 24 小时最多注册几个账号 |

**怎么设置**：后台签到设置里，4 项都能单独开关和填数字。

---

### 7. 在线客服预设
**做什么**：后台可以配客服信息（QQ、微信、Telegram、链接等），前台自动展示。

**展示形态**：会自适应——电脑上是浮窗，手机上是底部条，首页和控制台都能显示。

---

### 8. 图片压缩直传（不用第三方图床）
**做什么**：上传 Logo、客服二维码时，图片在**浏览器里先压缩**再上传，既快又省空间。

**三种上传方式**：
- 点击选文件
- 直接把图片拖进去
- **`Ctrl+V` 粘贴**（截图后直接粘，最方便）

**安全**：后端会过滤 SVG 里的恶意脚本，并限制文件大小。

---

### 9. 报错信息脱敏（不暴露上游真实报错）
**做什么**：当上游 AI 服务报错时，用户看到的**不是**原始报错（可能包含渠道名、密钥信息、上游供应商名），而是你自定义的友好文案。

**内置**：已经预置了 **10 条常见报错**的中文/英文/繁体文案，开箱即用。

**可自定义**：你也可以加自己的规则——填关键词 + 你想显示的文案。

**多语言**：内置文案会跟着用户的语言自动切换（中/英/繁）。

**注意**：你自己写的规则**原样输出**，不会被翻译（因为那是你的话）。

---

### 10. 多语言支持
**做什么**：新增的功能全部支持多语言。

**覆盖**：前端 7 种语言（英、简中、繁中、日、法、俄、越），后端 3 种（英、简中、繁中）。

**质量保证**：7 个语言文件的键**完全对齐**——0 缺失、0 多余、0 重复。

---

### 11. 伪 200 拦截与自动换渠道 ⭐（这项设计改过，请重点看）

**问题背景**：有些上游 AI 服务会"假装成功"——HTTP 状态码返回 **200（成功）**，但正文其实是一句拒绝语，比如：

> "The prompt could not be submitted. The prompt contains sensitive words that violate Google's Generative AI Prohibited Use policy."

如果不处理，用户会**花钱买到一个拒绝回答**。

**我们做什么**：识别出这种"假成功"，然后**自动换一个渠道重试**。重试成功用户拿到答案；全部失败则**退款**。

**重要：这项功能是"每个渠道单独设置"的**

- **一个渠道一个开关**——开哪个渠道就只对那个渠道生效
- **渠道之间互相独立**，互不影响
- **没有全局开关**（这是你明确要求的）

**怎么设置**：
1. 进入**渠道编辑**页面
2. 切到「**请求与响应**」标签
3. 找到「伪 200 检测」开关，打开
4. 打开后会多出一个文本框，可以填**你自己的拦截特征**（可选，不填就用内置的）

**误判问题已解决**：早期版本会因为"正常回答里提到了这些词"而误判。现在我们用了**更聪明的判断方式**（要求正文**以拒绝语开头**，而不是"只要出现这些词就算"）。

**实测结果**：
- 14 条正常内容（比如"解释 Google 的政策"、"翻译这句话"、"教程里引用这个报错"）→ **全部不误判** ✅
- 4 条真实上游拒绝 → **全部准确识别** ✅

**不会误封渠道**：这里有一个"保险丝"——提示词被拦截**绝不会导致渠道被封**。即使你把这句报错文案填进"自动封禁关键词"里，渠道也不会被封（我们做了显式保护，不是靠巧合）。

## 三、你最关心的三件事

### ✅ 1. 数据库不会被破坏

**没有**给官方已有的表加任何字段，**没有**执行任何改表操作。

唯一新增的是**一张独立的返佣流水表**（`affiliate_rewards`），用来记录"谁给谁返了多少佣"。这张表和官方表完全无关，官方升级时不会有任何冲突。

其他所有配置（开关、比例、文案）都存进官方原有的配置表里，**不需要改表结构**。

**为什么这很重要**：改表结构是最容易出事故的操作（数据丢失、升级失败）。我们完全避免了。

---

### ✅ 2. 没有外部脚本/后台进程

**没有** Python 脚本、**没有** Node.js 定时任务、**没有**需要单独启动的辅助程序。

所有功能都在主程序内部完成。**好处**：
- 部署简单（就一个容器）
- 不会因为脚本挂了导致功能失效
- 支持多实例部署（可以水平扩容）

---

### ✅ 3. 官方代码改动极少，容易升级

**只改了 109 个文件**（其中 30 个是新增的），而且都是**必要的最小改动**。

我们**特意排除**了所有与业务无关的改动：
- 页脚、关于页、Logo 提示文字 → 保持官方原版
- 全局样式、底层 UI 组件 → **完全没碰**
- 官方首页 → **一个字没改**
- 官方原有的失败测试 → **一个没动**
- 版本号、CI 配置 → 没动

**为什么这很重要**：改动越少，以后官方更新时冲突越少，升级越省事。

### 升级后要做的检查

`UPGRADE_GUIDE.md` 第 4.3 节有一段现成的命令，跑一遍就知道有没有问题。

## 六、有哪些"坑"需要知道？

### 1. 有 3 个官方自带的问题，我们**故意没修**

因为这些是官方自己的问题，修了反而会和官方版本冲突：

| 问题 | 说明 |
|---|---|
| 个别测试偶发失败 | 官方原版同样会失败，是测试本身的时序问题 |
| Windows 下 SQLite 文件占用 | 环境问题，Linux 部署无影响 |
| 前端全量测试偶尔抖动 | 机器资源紧张时的 jsdom 时序问题，单独跑必过 |

**处理原则**：官方的问题不碰，只在文档里记录。

### 2. 没验证过的部分（如实说明）

| 项 | 情况 |
|---|---|
| MySQL / PostgreSQL | **没有实测**。我们只用了标准写法、没用数据库特有功能，但**没有**三数据库的实测证据。如果你用 MySQL/PG，建议先测试环境验证。 |
| 并发安全测试 | 无法开启 `-race` 检测（环境限制），但用行为测试证明了：16 个并发请求 → 只有 1 个成功、1 条流水、额度只入账 1 次 |
| 真实浏览器 | 前端只验证到"页面元素和提交数据正确"，**没有**在真实浏览器里人工点过 |

### 3. 伪 200 检测的一个取舍

我们的判断方式是"**正文必须以拒绝语开头**"。好处是几乎不误判，代价是：

如果某个上游把拒绝语放在**正文中间**（先输出一段前缀再拒绝），可能会**漏检**。

**解决办法**：如果你遇到漏检，把那个上游的拒绝特征填进渠道的「自定义拦截特征」框里就行——这正是自定义功能的价值。
